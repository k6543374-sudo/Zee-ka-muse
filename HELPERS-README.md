# OpenMuse + 4 helper agents (changes by Instinct for Kartik)

Base: CopilotKit/OpenMuse (MIT), shallow clone. Changes:
- `apps/server/src/engine/helpers.ts` (new): four advice-only helper agents exposed as tools:
  `ask_planner`, `ask_researcher`, `ask_reviewer`, `ask_writer`. Each is a separate tool-less model call with its own role prompt. They cannot act; the main agent keeps actions/approvals.
- `engine/conversation.ts`: registers the helpers when `AGENT_BACKEND=model`, and mentions them in the system prompt.
- `engine/tanstack-agent.ts`: `adapter` exported (one word).
- `tests/helpers-agents.test.ts`: 4 tests (unit with fake runner; wire tests against local fixture servers: Chat Completions stream, stalled gateway timeout/cancel). Helper calls time out after 45s (HELPER_TIMEOUT_MS).
- `apps/server/src/storage.ts` (new) + `files.ts`/`config.ts`/`app.ts`: optional file mirror to a private Supabase Storage bucket. Every imported PDF is uploaded on import and lazily re-downloaded (and re-cached locally) when a read finds no local file, so files survive a host wiping DATA_DIR on restart. Upload failure warns and never rejects the import.
- `tests/files-storage.test.ts`: 5 tests against a fake bucket (mirror on import, restore after local wipe, upload-failure warning, no-network without a remote, missing remote object).

## Supabase (free) persistence setup
Database records:
- Create a free Supabase project, then in Dashboard > Connect copy the SESSION POOLER string (IPv4-safe; the direct db.<ref>.supabase.co host is IPv6-only without a paid add-on).
- Set DATABASE_URL to it, e.g. postgresql://postgres.<ref>:<password>@<pooler-host>:5432/postgres?sslmode=require
- db.ts then uses real Postgres instead of embedded PGlite. Free tier: 500 MB database; a project pauses after 1 week of no activity and is restored from the dashboard.

Files (uploaded/downloaded PDFs):
- Create a PRIVATE bucket, then set:
  SUPABASE_URL=https://<ref>.supabase.co
  SUPABASE_SERVICE_KEY=<service role key - server only, never in the browser>
  SUPABASE_STORAGE_BUCKET=<bucket name>   (default: openmuse-files)
- SUPABASE_URL and SUPABASE_SERVICE_KEY must be set together; with both unset the app keeps local-only file storage (files are lost on restart).
- Free tier: 1 GB file storage.

Not persisted (still lost on restart): browser profiles / saved site logins in the worker (no reliable free way; re-login after restart is expected).

## Free Render deploy (render.free.yaml, added Nov 6)
- Blueprint: render.free.yaml (plan: free, no disks, no browser worker).
- REQUIRED env (set in Render dashboard, sync:false): DATABASE_URL (Supabase session pooler, sslmode=require), SUPABASE_URL, SUPABASE_SERVICE_KEY, CPK_INTELLIGENCE_API_KEY, CPK_TELEMETRY_ID, MODEL, OPENAI_BASE_URL, OPENAI_API_KEY.
- Without DATABASE_URL the free 512 MB instance OOMs on PGlite WASM before binding a port (known stock behavior, see render.yaml comment).
- Browser worker (page reads/screenshots/Take control) is NOT in the free blueprint: Chromium at 512 MB is OOM-risk and Render private services are paid. API boots without it.
- Free web services sleep after ~15 min idle; cold start tens of seconds. To keep it warm, point an UptimeRobot free monitor (5 min interval) at https://<your-service>.onrender.com/api/health.
- OPENMUSE_ACCESS_KEY is generated by the blueprint: the API requires this key; grab it from the Render dashboard env after first deploy.
